# Tuning Notes & Alert Shadowing Resolution

## The Conflict
A broad, legacy brute-force detection rule configured to trigger on total failure volume (`count() > 5`) from a single IP address intercepted the 15-failure burst generated by the password spray script before the targeted horizontal rule could process it.

## The Solution
1. Temporarily disabled the legacy volume-based rule during initial testing to isolate and validate the new horizontal password spray detection.
2. Tuned and re-enabled the legacy rule with strict mutual exclusivity by scoping the aggregation to individual account pairs (`by IpAddress, TargetUserName`) rather than total IP volume.

### Refined Single-Account Brute Force Rule Query
```kusto
SecurityEvent
| where TimeGenerated > ago(1h)
| where EventID == 4625
| summarize FailureCount = count(), StartTime = min(TimeGenerated), EndTime = max(TimeGenerated) by IpAddress, TargetUserName, WorkstationName, Computer
| where FailureCount >= 5
| extend ClientIP = IpAddress, TargetedAccount = TargetUserName
